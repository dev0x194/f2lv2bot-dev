`isolated_documents` preserves Test F by default. Selecting `provider_iframe` does
**not** activate arbitrary URLs. `FileStream/web/provider_iframes.py` contains an
empty, immutable `APPROVED_CONTRACTS` map. Environment variables cannot authorize
a host, endpoint or policy. There is no override flag or direct-script fallback.
Missing/invalid/unapproved URLs disable individual placements; an entirely
unverified configuration reports `mode_error=provider-contract-unverified`.
Unknown mode names disable banners. Existing global/per-bot/admin ad gates remain.

A future contract must be reviewed in source, match the exact configured URL,
size and publisher origin, and contain evidence and a reviewed iframe policy.
The browser also checks the configured publisher origin before mounting Test G.
Other publisher hostnames remain disabled unless explicitly implemented/reviewed.
Tests replace the registry temporarily with clearly synthetic `.test` contracts;
those endpoints are not examples of real Adsterra URLs and are never shipped as
production approvals.

Validation rejects non-HTTPS URLs, userinfo, nonstandard ports, local/IP origins,
publisher/child hosts, fragments, control characters, JavaScript invocation paths
and credential-looking query names. Exact endpoint approval rejects arbitrary
query additions and unapproved hosts/paths. Only fixed public URLs are used: page
tokens, media URLs, public-file metadata and session IDs are never appended.
Domain validation is lexical, not DNS authentication; official ownership, a
separate registrable domain, DNS and redirect behavior require contract review.

The current policy ceiling permits only reviewed `allow-scripts`,
`allow-same-origin` and optional `allow-popups` sandbox tokens. Top-navigation,
forms, downloads, popup sandbox escapes and storage-access grants are rejected.
Referrers are limited to `origin` or `no-referrer`. Camera, microphone,
geolocation, payment and USB permissions are denied. No actual provider sandbox
policy is approved by this scaffold. If required provider permissions/referrers
conflict with this ceiling, stop activation for explicit security review.

`allow-same-origin` preserves the external provider's own origin/storage; it does
not make that provider same-origin with FileStream. Its own cookies may still be
sent by the browser according to browser policy. The implementation does not
claim credentialless third-party requests or that a permissive sandbox is complete
isolation. Parent DOM protection requires a genuinely different provider origin;
FileStream keeps Secure/HttpOnly host-only `__Host-` session cookies. Existing CSP
is not broadened. Browser/child response CSP and navigation compatibility remain
part of the missing official contract.

## Four placements and lifecycle

- Mobile top 320x50 and bottom 300x250.
- Desktop top 728x90 and inline 300x250.
- Only active breakpoint units initialize; ordinary resizing does not refresh them.
- A matching 300x250 document is reused on the shared secondary placement across
  breakpoints. Frames stay attached; failed records are not retried automatically.
- No global atOptions is created and no provider JavaScript is inserted in the
  parent document. Existing V3 templates, layout and player controls are retained.
- Provider frames do not use FileStream's custom monitor-message protocol.
  `load` means `loaded-unverified`, never verified fill. A slow response keeps its
  dimensions and frame alive. Explicit error events fail the unit without retries.
- Cross-origin HTTP errors often fire load rather than error: reliable no-fill or
  HTTP-status detection requires an official provider reporting contract. The
  scaffold cannot inspect a provider's private DOM or infer creative visibility.

A provider may implement its own refresh/viewability logic inside a retained
frame. The parent cannot pause or audit that logic across origins. Official
frequency/impression rules must cover hidden/reused frames before activation;
the loader itself never schedules advertisement reloads.

Popunder and Social Bar are disabled in Test G even if existing optional settings
are enabled. They are not converted to iframes. Test F's optional isolated behavior
is preserved. Smartlink remains a separately labeled, optional, user-clicked link;
there are no automatic redirects. Source URLs/keys for all existing formats remain
unchanged. The earlier [direct-script audit](DIRECT-INTEGRATION-AUDIT.md) explains
why direct scripts are not a fallback. Its historical no-runtime-change statement
applied to that audit; this new task adds a disabled cross-origin scaffold.
